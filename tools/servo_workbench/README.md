# HD1910 舵机工作台

本地网页，可由电脑直接连接 URT-2，也可由 RDK X5 经 ESP32 桥接连接 URT-2。不需要浏览器支持 Web Serial，不依赖外部 CDN。

## 统一工作台入口

当前运控与校准连接使用 <http://127.0.0.1:8767/>。左侧功能栏包含设备状态、舵机工作台、机械零点、关节校准、IMU 校准，切换分区保留现有采样步骤；暂停或超时后不展示旧值为实时数据，历史诊断单独标明。

「机械零点」恢复逐舵机实测编码器、已保存零点和「选择并记零点」入口。选择需核对的关节，按 q=0 模型零姿态摆稳、确认支撑与参考后采样；至少 12 个连续静止样本跨越 350 毫秒后生成预览，另点保存才修改所选零点。保存前仍需当前反馈正常、姿态未离开候选位置，且没有未保存的方向/范围步骤。只重置该关节的方向和范围，其他关节及 IMU 保留；没有全部零点覆盖按钮。新零点带本机授权记录，可随校准在服务重启后恢复，不写舵机 EEPROM、不发送位置目标。

关节校准页的实时读数下方也直接提供同一组「记零点 / 保存零点 / 取消」控件，沿用当前关节选择和支撑确认，只需另外确认灰色模型零姿态。无需切换页面；切换功能时控件保留同一份预览，未保存的方向/范围必须明确取消后再重采零点。

统一页面的「舵机工作台」沿用旧版两栏布局，支持一键扫描 ID 和位置、扫描结果选择、位置/角度显示、读取与释放、改编号以及可编辑目标的缓慢回中。保留「恢复默认 2047」，并可填入保存的机械零点或当前位置；这些按钮只填写目标。维护与反馈采集互斥：必须先结束采集并取得串口关闭证明。随后用户点击一键扫描即可依次连接、检查固件能力并扫描，也可单独连接。打开页面、切换功能或刷新均不会启动维护连接。

这些功能需要支持 `XGODUCK_MAINT_1` 的 ESP32 运控固件；软件更新不代表固件已刷入或实机验证完成。进入时先查询能力，不兼容固件不会接受维护指令。已有供电/舵机故障或关闭证明缺失仍会阻止进入。

- 改编号仅允许总线上一只舵机，主机和固件都扫描验证；写入只尝试一次。编号写入前持久标记映射待复核，保存的校准不删除、不自动迁移，按旧映射回中和恢复整机校准受限。
- 回中可填写 `0–4095` 的整数目标，目标和当前位置必须在选定关节已确认的安全范围内，需要明确确认机身支撑。自定义目标不改保存的机械零点；旧客户端不传目标时仍使用机械零点。固件逐步移动、持续读回，成功后释放扭矩；10 秒未完成或维护通信超过 1 秒失联会退出。单关节范围不等于所有关节组合的碰撞验证。
- 点击「停止并退出维护」结束当前维护；连接所有权在串口关闭与 SSH 子进程退出均得到证明后释放。读写错误不自动重试。

下文的 8765 工作台仍用于 USB 直连，或支持 `workbench_xfer` 的旧桥接固件；旧桥接使用 115200 bps、ASCII 协议，不能直接连接当前 921600 bps 的二进制运控固件。两个后台不能同时访问同一串口。统一维护协议位于 `tools/esp32_motion/README.md`，主机及界面位于 `tools/x5_recovery/`。

### 自行恢复校准采集

采集结束后，直接点击当前页顶部的「继续 IMU 采集」或「继续关节采集」，无需在聊天里重新开启。连续 0.6 秒收不到新反馈时会暂停，避免记录过时读数；这个阈值不是校准到期时间。右上角采集状态可点击，跳到停止原因和继续入口。

若 SSH 断开而没有收到旧串口关闭报告，页面提供「检查连接并继续」。一次点击先做只读的板卡、存储、内核日志和两次串口占用检查，确认旧连接不再占用串口后，才尝试建立一次 HELLO/STATE 采集连接。新连接仍须取得串口独占并通过连续推进的新鲜反馈检查。这是重新核对实际占用状态，不会补造旧关闭报告、终止板端进程或自动重试。检查失败的具体原因显示在同一区域；保存的零点、IMU 和已完成关节不清除。

IMU 页面要求 URT2 电池断开、X5 与 ESP32 保持供电；通过离线 IMU 检查只开放 IMU 采样，仍保留舵机供电待复查限制。关节页面的复查要求 15 个舵机全部在线、无故障、控制器未使能且扭矩关闭。存储、内核、身份或连接关闭检查失败时仍保持暂停，并在页面显示原因。

## 启动：USB 直连 URT-2

需要 Python 3.10 或更新版本。首次运行会在本目录创建 `.venv` 并安装 `pyserial==3.5`：

```sh
./tools/servo_workbench/run.sh
```

打开 <http://127.0.0.1:8765>。如端口被占用，可使用 `./tools/servo_workbench/run.sh --port 8766`。退出服务按 Ctrl+C。

也可以使用已有 Python 环境：`python3 -m pip install -r tools/servo_workbench/requirements.txt`，然后 `python3 tools/servo_workbench/app.py`。

## 启动：X5 → ESP32 → URT-2

先将 ESP32 更新为支持 `workbench_xfer` 的 **0.2 固件**。现有 0.1 只读诊断固件需要更新，不能直接用于工作台桥接。固件说明见 [ESP32 固件 README](../esp32_linkcheck/firmware/README.md)。

本次部署到 X5 的 `/root/xgoduck-servo-workbench` 后，推荐在笔记本的项目根目录执行：

```sh
./tools/servo_workbench/connect_x5.sh
```

脚本默认连接 `root@192.168.1.11`（2026-10-10 用户切换网络后的地址），启动或复用 X5 上的 ESP32 工作台，并建立到笔记本 8765 的 SSH 隧道。SSH 会正常提示输入密码，或使用已有 SSH 密钥；脚本不保存密码。看到就绪提示后打开 <http://127.0.0.1:8765>，保持这个终端窗口运行。按 Ctrl+C 关闭隧道，X5 上的网页服务继续运行；再次执行脚本会复用已有服务，不中断正在进行的操作。更换 X5 地址时可传入 `./tools/servo_workbench/connect_x5.sh root@新地址` 或设置 `XGO_X5_TARGET`。脚本不负责首次上传程序或安装依赖。

也可以按以下方式手动启动。在 X5 的项目目录运行：

```sh
cd tools/servo_workbench
python3 -m pip install -r requirements.txt
python3 app.py --esp32-bridge --bridge-port /dev/ttyUSB0
```

服务仍只监听 X5 的 `127.0.0.1:8765`。在笔记本的另一个终端建立 SSH 隧道：

```sh
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 root@192.168.1.11
```

然后在笔记本打开 <http://127.0.0.1:8765>，保持 SSH 终端运行。笔记本与 X5 使用同一个端口 8765，使浏览器的 Host/Origin 与工作台校验一致；笔记本上不要同时启动另一个占用该端口的工作台服务。

页面显示链路 **X5 → ESP32 → URT-2**，使用显式指定的 `/dev/ttyUSB0`。X5 与 ESP32 的主机串口（COM）固定 **115200 bps**，ESP32 与 URT-2 的舵机总线固定 **1000000 bps**；页面的波特率选择指舵机总线，桥接模式只允许 1M。直连模式的波特率选择保持原样。

两种模式的接线要区分：

| 模式 | 控制链路 | URT-2 信号电平档位 |
| --- | --- | --- |
| USB 直连 | 电脑 USB → URT-2 → TTL 舵机口 | 5V，沿用本机直连配置 |
| ESP32 桥接 | X5 USB → ESP32；GPIO17（TX）→ URT-2 TXD，GPIO18（RX）→ URT-2 RXD，GND → GND | **3V3**，匹配 ESP32 I/O |

桥接时 URT-2 的 USB 不连接，舵机继续由原有电池经 V1/G 供电。此处的 3V3 档是通信信号电平，不是舵机电源；上表没有要求额外并接 ESP32 与 URT-2 的 5V。V1 是否同时给通信电路供电、5V 排针的供电方向尚未由现有资料确认，不能根据直连模式推断桥接供电。

桥接复用下述扫描、读取、回中、停止和修改 ID 功能。打开页面与后台轮询仍只读取状态；只有点击回中、停止并释放、写入 ID 等操作按钮时才发送相应写入。USB 断开或响应丢失后，程序不会自动重放写入。浏览器断开不代表后台动作已取消，已经开始的动作可能继续到结束；USB 断线也不代表舵机已经停止。

## 使用

1. 首次使用连接 **一只 HD1910**，保持输出盘无连杆、无阻挡。USB 直连时使用上方直连接法与 5V 信号档；ESP32 桥接时使用桥接接法与 **3V3 信号档**。
2. 直连模式自动识别 CH343 URT-2（USB VID:PID 1A86:55D3），以 1 Mbps 查询 ID 1。其他串口可在“连接设置”选择。桥接模式使用启动参数指定的 ESP32 串口，页面分别显示主机串口与舵机总线速率。
3. “检测连接 / 读取 ID”查询所选 ID。点击页面最顶部的“一键扫描 ID 和位置”，逐个查询 0–253，列表显示每只响应舵机的 ID、扫描时的位置及编码器角度；扫描结果可点击选择。重新扫描会清除上次的扫描结果。已插 USB 与舵机有响应是两种不同状态。
4. “读取当前位置”立即读取当前查询 ID 的真实位置，并在操作记录中保存这次读数。页面同时自动刷新位置；读取不会转动舵机或改变扭矩。回中默认目标 **2047**，可修改为 0–4095 的整数。点击回中按钮后按小步位置指令移动，连续三次读取最终位置；±12 刻度以内视为到位，页面保留真实位置，不把它伪装成目标值。
5. “停止并释放”取消正在进行的回中并关闭扭矩；空闲时可释放当前舵机。释放后输出盘不再保持位置。断线情况下软件不能保证停止，请断开舵机电源。
6. 修改 ID：在扫描结果中选中要修改的舵机，再输入新 ID。可以同时连接多只不同 ID 的舵机；程序先扫描总线，检查所选 ID 有响应、目标编号未占用，然后**关闭扭矩并确认读回为 0**，再解锁参数区、写 ID、以新 ID 读取并重新锁定参数区。修改后保持扭矩释放，不会自动重新回中。**扫描无法区分同 ID 的多只舵机**，若有同 ID 的舵机，必须分开连接设置。即时 ID 和锁标志读回只证明当前状态，不代表断电保存已通过验证；请让同一只舵机完全断电后重新连接，再扫描确认新 ID。

打开页面、自动轮询、检测和扫描仅发送读取指令。回中是位置控制，不会修改零点偏移、PID、波特率或校准参数。修改 ID 只在点击相应按钮时执行。

USB 曾在本机成功完成单只空载 HD1910 的回中，但不保证不同 USB 口、线材或负载都能工作。厂家要求舵机转动使用独立供电，多舵机及带载操作应使用符合 HD1910 **4–8.4V** 规格的电源。

服务只监听 `127.0.0.1`，使用 Host/Origin 校验和会话令牌防止其他网页触发硬件操作。不要将它暴露到局域网或互联网。同一时间只允许一个操作占用串口；不要同时运行其他串口调试软件。

## 验证与协议来源

```sh
cd tools/servo_workbench
.venv/bin/python -m unittest discover -v
```

测试使用模拟舵机验证协议校验、回中、断线处理和 ID 变更，不会操作真实硬件。实机读取可在网页直接验证；本次桥接接入不代用户点击回中或修改真实舵机 ID。

- [XGO 官方固件寄存器与协议](https://github.com/LuwuDynamics/xgoduck_runtime_arduino/tree/8cdbbd84710d856581982c9eaf0d5e2970666232/sketch)：ID 5、扭矩 40、目标位置 42、锁定 55、当前位置 56。
- [飞特协议手册](https://www.feetech.cn/Data/feetechrc/upload/file/20240702/舵机协议手册-磁编码版本.pdf)：写入 ID 前解锁 EPROM。
- [飞特 HLS/HTS SDK](https://github.com/ftservo/FTServo_Arduino/blob/main/src/HLSCL.cpp)：`unLockEprom` 先关闭扭矩再解锁，`LockEprom` 重新锁定。不要沿用 SMS/STS 实现而遗漏关闭扭矩。

适用对象是本项目 HD1910 的单圈位置模式，不作为其他型号舵机的通用烧录或校准工具。

已记录舵机：扫描、成功读取、收到有效故障回复或修改编号后，自动在本机 `known_servos.json` 保存已知 ID。后台轮询已知 ID，区分在线、在线报故障、离线（无有效响应）、待检测。适配器/服务断开时显示待检测，操作占用串口时暂停轮询；故障舵机不会中断全总线扫描。编号代表总线地址，不是硬件唯一身份；修改 ID 后列表替换旧编号。同 ID 的多只舵机仍无法区分。
